# 代码分析与优化记录（2026-11-19）

本轮以 `c36b5c5` 为基线，检查主窗口、数据读写、Git 上传/拉取、搜索、导出、设置与卡片渲染。运行环境为 macOS、Python 3.13、Flet 0.82.2。

## 已完成的改进

| 方面 | 发现的问题 | 修改后的行为 |
| --- | --- | --- |
| 职责划分 | 数据格式校验与读写耦合，目录选择实现重复 | 提取 `data_schema`、`search_index`、`file_dialog_service`、`file_lock`，各入口使用同一套校验和平台接口 |
| 搜索性能 | 每次搜索都重新转换长正文；异步事件中直接执行计算 | 按对象与更新时间缓存搜索文本，后台计算；校验输入代次、当前页面和数据版本后才应用结果 |
| 输入响应 | 过期防抖任务继续等待；没有立即搜索或清空入口 | 取消旧防抖任务，回车立即搜索，提供清空按钮；切换页面后旧结果不会覆盖当前页面 |
| 导出与目录选择 | `thread.join()` 等待选择器，混用 AppleScript/tkinter | 复用原生异步 FilePicker；后台序列化、写文件；导出点击时的数据快照 |
| 数据完整性 | 空对象或错误字段类型可通过校验，指令可能引用不存在的板块 | 校验根结构、字段类型、枚举、重复 ID 和板块关联；兼容早期没有任务/问题字段的数据 |
| 多窗口保存 | 过期窗口可以覆盖其他窗口或外部程序的修改 | 写入前用文件版本、内容摘要及短期跨进程锁检查；冲突时拒绝覆盖，退出时将未保存修改另存为 `data_local_*.json` |
| 备份恢复 | 只校验 JSON 语法，可能先覆盖再发现错误 | 恢复前确认、完整校验、备份当前数据；原子替换成功后再替换内存；恢复失败保留设置窗口 |
| 启动恢复 | 配置损坏可能启动异常；数据损坏后可能生成空数据 | 保留损坏配置副本；数据无法读取时显示重试及选择目录入口，不用空数据覆盖原文件 |
| 配置保存 | 配置直接覆盖写入，更新线程与界面都可能保存 | 加锁、临时文件与原子替换；失败时回滚内存中的设置值 |
| Git 连接 | 固定 main，网络与认证可能长时间等待 | 优先跟踪分支/远程 HEAD，兼容 master；各网络命令设 45 秒超时，保留自定义 SSH 配置 |
| 卡片体验 | 长解答占满视口，窄窗口的侧栏挤压正文 | 长解答默认显示六行，可展开；侧栏在窄窗口自动收窄，板块管理放入菜单；筛选控件同步缩小 |
| 分页与状态 | 原列表原地新增无法触发分页重置，换排序可能留在旧页 | 使用独立 ID 快照，新增和换排序回第一页；统一上传、拉取和关闭时的编辑禁用处理 |

## 测量结果

搜索数据集为 10,000 条指令，每条正文包含 300 组中英文说明，查询词不命中；连续七次取中位数。以下是计算耗时，不代表用户感知的完整操作时间，也不包含 200 ms 输入防抖。

| 项目 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 首次搜索 | 129.7 ms | 169.4 ms |
| 缓存后的连续搜索中位数 | 125.0 ms | 31.5 ms |
| 1,000 条指令的缓存搜索 | — | 3.1 ms |
| 已访问板块切换的补丁生成 | 约 2.5 ms | 约 2.6 ms |
| 1,000 条指令数据中的保存交互 | 约 7.6 ms | 约 7.7 ms |

连续搜索耗时约降低 75%。首次建立缓存有额外计算与内存开销，已移到后台；板块切换和普通保存的微小差异应视为运行波动，本轮没有证据表明它们进一步加速。

可复验命令：

```bash

python -m tests.benchmark_search
python -m tests.benchmark_interactions
python -m tests.visual_regression
```

## 后续值得单独推进的事项

- `app.py` 仍集中管理较多界面协调逻辑。可继续按指令、任务、问题拆分控制器，保持现有交互及回归测试。
- 普通 Git JSON 文本冲突仍会安全中止。按记录 ID 做三方合并可减少冲突，但需要覆盖删除与编辑冲突、相同字段修改及排序变化等语义。
- 搜索缓存会额外保存规范化文本。更大数据集应进一步测量内存占用，决定缓存容量或持久化索引方案。
- Windows 单文件包的启动耗时需要实机测量，再决定是否增加目录版发行包；当前没有启动提速的测量结论。
